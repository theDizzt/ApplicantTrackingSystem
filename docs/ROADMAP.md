# 개발 로드맵

핵심 컨셉은 **"왜 떨어졌는가"** 와 **"면접 대비"** 두 가지입니다. 모든 기능은 "내가 이 회사에 얼마나 적합한가"를 보여주고 강점을 어필하도록 돕는 방향으로 만듭니다.

## 우선순위

| 순서 | 작업 | 내용 | 상태 |
|---|---|---|---|
| 1 | 심사 결과 구조화 + 근거 시각화 | AI 응답을 "항목별 점수 · 근거 문장 · 부족한 요건" 구조로 바꾸고 심사 결과 화면에 표시 | 진행 중 |
| 2 | 불합격 예상 원인 리포트 | 1의 부족한 요건을 모아 "떨어질 수 있는 이유 Top 3"와 "이렇게 어필하세요"로 정리 | 예정 |
| 3 | 꼬리 질문 면접 | 1·2에서 찾은 약점으로 면접 질문을 만들고, 답변에 따라 꼬리 질문을 이어감. 음성 답변은 기존 녹음·STT 재사용 | 예정 |
| 4 | 모델 역할 분리 | 심사 / 근거 추출 / 면접 / STT / 경량 작업에 모델 5개 정도를 나눠 토큰 비용 절감 | 예정 |
| 5 | 편의 기능 | 캘린더·발표일 알림, 자격증·프로젝트·공모전 항목, 이력서 항목 통합 관리, 영어 판독, 모바일 지원, 실시간 모의 면접 | 예정 |

## 1번을 먼저 하는 이유

- 서류 심사 결과는 이미 DB(`lib/db/src/schema/analyses.ts`)에 저장되고 있지만, 점수마다 피드백이 문장 하나뿐이라 "왜 이 점수인지"를 보여줄 수 없습니다.
- 근거를 구조화해 두면 점수 시각화, 불합격 원인 리포트, 약점 기반 면접 질문(2·3번)에 그대로 다시 쓸 수 있습니다.
- 새 기능을 처음부터 만드는 대신 기존 심사 기능을 확장하는 작업이라 위험이 작습니다.

## 참고 사항

- 회사 입장에서 보는 심사 기준도 반영합니다: 논문 등급과 저자 순서, AI 작성 문장 탐지, 장기 근속 가능성 판단.
- 단순히 스펙을 높이라고 하기보다, 지원자의 강점을 회사에 맞춰 어필하는 방향으로 피드백합니다.
- 클라우드 환경에 배포해 바로 테스트할 수 있게 할 예정입니다. 코드는 자유롭게 수정하고, 기능이 겹쳐도 괜찮습니다.
