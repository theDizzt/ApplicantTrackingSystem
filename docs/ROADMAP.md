# 개발 로드맵

핵심 컨셉은 **"왜 떨어졌는가"** 와 **"면접 대비"** 두 가지입니다. 모든 기능은 "내가 이 회사에 얼마나 적합한가"를 보여주고 강점을 어필하도록 돕는 방향으로 만듭니다.

## 우선순위

| 순서 | 작업 | 내용 | 상태 |
|---|---|---|---|
| 1 | 심사 결과 구조화 + 근거 시각화 | AI 응답을 "항목별 점수 · 근거 문장 · 부족한 요건" 구조로 바꾸고 심사 결과 화면에 표시 | 구현 완료 (실환경 확인 전) |
| 2 | 불합격 예상 원인 리포트 | 1의 부족한 요건을 모아 "떨어질 수 있는 이유 Top 3"와 "이렇게 어필하세요"로 정리 | 구현 완료 (실환경 확인 전) |
| 3 | 꼬리 질문 면접 | 1·2에서 찾은 약점으로 면접 질문을 만들고, 답변에 따라 꼬리 질문을 이어감. 음성 답변은 기존 녹음·STT 재사용 | 약점 질문·꼬리 질문 구현 완료 (실환경 확인 전), 음성 답변 예정 |
| 4 | 모델 역할 분리 | 심사 / 근거 추출 / 면접 / STT / 경량 작업에 모델 5개 정도를 나눠 토큰 비용 절감 | 구현 완료 (실환경 확인 전) — 심사(기본)·면접·경량·이미지 인식 역할별 모델 + STT·임베딩. 관리자 페이지 › AI 설정 › 역할별 모델 |
| 5 | 편의 기능 | 캘린더·발표일 알림, 자격증·프로젝트·공모전 항목, 이력서 항목 통합 관리, 영어 판독, 모바일 지원, 실시간 모의 면접 | 일부 구현 (실환경 확인 전) — 지원 일정 캘린더·알림, 이력 항목 관리·이력서에 넣기. 영어 판독·실시간 모의 면접 예정 |

## 1번을 먼저 하는 이유

- 서류 심사 결과는 이미 DB(`lib/db/src/schema/analyses.ts`)에 저장되고 있지만, 점수마다 피드백이 문장 하나뿐이라 "왜 이 점수인지"를 보여줄 수 없습니다.
- 근거를 구조화해 두면 점수 시각화, 불합격 원인 리포트, 약점 기반 면접 질문(2·3번)에 그대로 다시 쓸 수 있습니다.
- 새 기능을 처음부터 만드는 대신 기존 심사 기능을 확장하는 작업이라 위험이 작습니다.

## 참고 사항

- 회사 입장에서 보는 심사 기준도 반영합니다: 논문 등급과 저자 순서, AI 작성 문장 탐지, 장기 근속 가능성 판단.
- 단순히 스펙을 높이라고 하기보다, 지원자의 강점을 회사에 맞춰 어필하는 방향으로 피드백합니다.
- 클라우드 환경에 배포해 바로 테스트할 수 있게 할 예정입니다. 코드는 자유롭게 수정하고, 기능이 겹쳐도 괜찮습니다.

## 4번 모델 역할 분리 — 구성 (2026-11-10)

같은 API 키·주소를 쓰고 역할마다 모델만 바꿉니다. 비워 둔 역할은 기본 모델을 씁니다 (`lib/openai.ts`의 `getAI(role)`).

| 역할 | 쓰는 곳 | 설정 키 | 현재 값 (HASA) |
|---|---|---|---|
| 기본(심사) | 서류 심사 3종, 불합격 원인 리포트, 모델별 의견, 커리어 분석, 자기소개서 작성 | `ai_model` | `hyperclovax-seed-32b` |
| 면접 | 면접 질문 생성, 답변 평가, 꼬리 질문 | `ai_model_interview` | `exaone-4.0-32b` |
| 경량 | 맞춤법, 이력서 파일 구조화, 기업 추천·매칭, 녹음용 질문 | `ai_model_light` | `gemma-4-31b` |
| 이미지 인식 | 스캔 PDF·이미지 공고 OCR | `ai_model_vision` | `qwen3-vl-32b` |
| STT | 음성 자기소개서 | `ai_stt_model` | `whisper-large-v3-turbo` |
| 임베딩 | 직무 문장 유사도 | `ai_embedding_model` | 미설정 (비활성) |
| 보조 심사 2·3 | 서류 심사 모델별 의견 | `ai2_*`, `ai3_*` | `exaone-4.0-32b`, `solar-open-100b` |

- 임베딩은 `bge-m3`가 동작하지만, 유사도 기준(60점)이 OpenAI 임베딩에 맞춰져 있어 그대로 켜면 거의 모든 심사에 "유사도 낮음"이 붙습니다 (테스트: 관련 문장 54점, 무관 문장 43점). 켜려면 기준값 보정이 먼저 필요합니다.
- HASA 무료 키의 하루 한도(500회)는 키 단위라, 역할을 나눠도 호출 수는 줄지 않습니다. 비용·속도·품질을 역할에 맞추는 효과만 있습니다.

## 5번 편의 기능 — 1차 구현 (2026-11-11)

| 기능 | 화면 | 내용 |
|---|---|---|
| 지원 일정 | 메뉴 › 지원 일정 (`/schedule`) | 회사별 서류 마감일·결과 발표일·면접일과 지원 상태(관심~최종 합격·불합격)를 월 달력과 "다가오는 일정"으로 표시. 날짜는 지원 회사 수정 화면의 "지원 일정"에서 입력 |
| 일정 알림 | 메뉴 배지·대시보드 배너·브라우저 알림 | 오늘~3일 뒤 일정 수를 메뉴에 배지로, 대시보드에 배너로 표시. "브라우저 알림 켜기"를 누르면 앱을 열어 둔 동안 일정마다 하루 한 번 브라우저 알림. 최종 합격·불합격 회사의 마감·면접은 제외 |
| 이력 항목 | 메뉴 › 이력 항목 (`/profile`) | 자격증·어학·프로젝트·수상/공모전·대외활동·경력·교육을 한 곳에 등록·수정·삭제 (`profile_items` 테이블, `/api/profile-items`) |
| 이력서에 넣기 | 이력서 편집 › "이력 항목 넣기" | 고른 항목을 종류별 소제목·목록으로 이력서 내용 끝에 붙임. 저장해야 반영 |

- DB: `companies`에 `application_status`, `deadline_date`, `announcement_date`, `interview_date` 열, 새 테이블 `profile_items` (`pnpm --filter @workspace/db run push`로 적용).
- 알림은 서버 푸시가 아니라 브라우저가 앱을 열어 둔 동안만 동작합니다. 이메일·휴대폰 알림은 아직 없습니다.
- 모바일: 새 화면은 좁은 화면에서 달력 칸을 점으로 줄이고, 메뉴 버튼에 일정 표시 점을 띄웁니다. 기존 화면 전체의 모바일 점검은 따로 해야 합니다.

## 실시간 음성 면접 — 1단계 구현 (2026-11-21)

면접 연습 시작 화면에서 "실시간 음성 면접"을 고르면, AI 면접관이 질문을 소리 내어 읽고 지원자가 말로 답합니다. 답변마다 바로 평가하고 꼬리 질문을 이어갑니다. 상태: 구현 완료 (실환경 확인 전).

| 항목 | 내용 |
|---|---|
| 화면 | `/interviews/:id/live`. 질문 읽기(브라우저 TTS, 한국어 음성이 없으면 글로만) → 녹음(답변당 최대 3분) → "답변 완료" → 다음 질문. 중간에 끝내기, 나중에 이어서 하기 가능. 점수는 면접이 끝난 뒤에만 표시 |
| 서버 | `POST /interviews/:id/live/answers/:questionId` (음성 → STT → 바로 평가 → 꼬리 질문 추가), `POST /interviews/:id/live/finish` (종합 평가, 답하지 않은 꼬리 질문은 삭제) |
| 음성 처리 | 음성 자기소개서의 업로드·ffmpeg 변환·STT 코드를 `lib/audio-transcription.ts`로 옮겨 함께 사용 |
| DB | `interview_sessions.mode` (`text` / `live`) 열 추가 — `pnpm --filter @workspace/db run push` 필요 |
| AI 호출 수 | 면접 1회에 질문 생성 1 + 답변마다 1 + 종합 평가 1 (기본 5문항 + 꼬리 질문 최대 2단계면 최대 17회). HASA 하루 한도 500회 주의 |

### 2단계 — 면접 난이도 · 압박/긍정 꼬리 질문 (2026-11-22)

면접을 만들 때 난이도(하/중/상)를 고릅니다. 글로 답하기·실시간 음성 면접 모두 적용됩니다. 상태: 구현 완료 (실환경 확인 전).

| 난이도 | 기본 질문 | 꼬리 질문 단계 | 면접 전체 꼬리 질문 | 꼬리 질문 말투 (답변 점수 기준) |
|---|---|---|---|---|
| 하 | 지원 동기·경험 소개 등 기본 질문, 압박 없음, 너그럽게 채점 | 1 | 3개 | 70점 미만 확인 · 70점 이상 긍정 (압박 없음) |
| 중 | 경험 검증 + 직무 역량, 실제 면접 기준 채점 | 2 | 5개 | 60점 미만 압박 · 60~79 확인 · 80 이상 긍정 |
| 상 | 5개 중 2개 이상 압박 질문(약점·공백 지적, 반박, 곤란한 가정), 엄격 채점 | 2 | 7개 | 80점 미만 압박 · 80~89 확인 · 90 이상 긍정 |

- 말투 규칙은 AI에게도 알려 주고, 저장·표시하는 말투(`interview_questions.tone`)는 서버가 점수로 다시 계산합니다. 결과 화면의 꼬리 질문에 "압박 / 확인 / 긍정" 배지로 표시합니다. 실시간 면접 중에는 보여 주지 않습니다.
- 모든 난이도에서 사적인 질문(외모·나이·성별·가족·종교·출신 지역), 인신공격, 모욕은 금지합니다.
- 토큰 절약: 면접 전체 꼬리 질문 수에 상한을 둡니다. 글로 답하기 평가에서 상한보다 꼬리 질문이 많으면 점수가 낮은 답변부터 붙입니다. 답변마다 반복해서 보내는 호출(꼬리 질문·실시간 답변)에서는 인재상 600자, 채용공고 1,500자까지만 보냅니다.
- 최대 AI 호출 수 (기본 질문 5개 기준, 질문 생성·종합 평가 포함): 하 10회 · 중 12회 · 상 14회 (이전 17회).
- DB: `interview_sessions.difficulty`(기본 `normal`), `interview_questions.tone` 열 추가 — `pnpm --filter @workspace/db run push` 필요.

### 3단계 — 말버릇 분석 (2026-11-23)

실시간 음성 면접이 끝나면 결과 화면에 "말버릇 분석" 카드가 나옵니다. AI를 부르지 않고 서버가 규칙으로 계산하므로 토큰이 들지 않습니다. 상태: 구현 완료 (실환경 확인 전).

| 항목 | 계산 방법 |
|---|---|
| 말 속도 | 답변 음절 수 ÷ 녹음 길이 (분당 음절). 200 미만 느림 · 350 초과 빠름 (참고 기준) |
| 간투사 | "음·어·아·흠·엄·에"가 단어 하나로 나온 횟수와 1분당 횟수 |
| 습관어 | 이제·약간·그냥·막·좀·진짜·되게·사실·그러니까·뭔가·일단·솔직히·아무튼·뭐·정말·너무 |
| 습관 표현 | ~것 같습니다, ~같은 경우, ~부분, 어떻게 보면, 뭐랄까, 그런 식으로, ~라고 해야 할까 |
| 반복 단어 | 질문에 없는 단어를 조사를 떼고 세어, 3회 이상이면서 전체 단어의 1.5% 이상인 것 (최대 5개) |
| 답변 길이 | 15초 미만은 짧음, 2분 30초 초과는 긺 |
| 연습 포인트 | 위 결과가 기준을 넘으면 고칠 방법을 문장으로 제시 |

- 녹음 길이는 서버가 변환한 WAV 길이로 계산해 `interview_questions.answer_seconds`에 저장합니다 — `pnpm --filter @workspace/db run push` 필요.
- STT에 "음, 어…" 같은 받아쓰기 예시(prompt)를 줘서 군말을 지우지 않게 유도합니다. 그래도 STT가 군말을 빼고 적을 수 있어 실제보다 적게 셀 수 있습니다(화면에 안내).
- 분석 결과는 저장하지 않고 조회할 때마다 계산합니다. 단어 목록이나 기준을 바꾸면 이전 면접 결과에도 바로 반영됩니다 (`artifacts/api-server/src/lib/speech-habits.ts`).
- 종합 평가 AI에는 숫자 요약 한 줄만 붙여, 종합 피드백에서 말버릇도 언급할 수 있게 했습니다.

### 질문 단문화 (2026-11-24)

- 기본 질문·꼬리 질문(텍스트·음성 면접 모두) 생성 프롬프트에 `QUESTION_LENGTH_RULE`을 넣었습니다: 한 번에 한 가지만, 한 문장(최대 두 문장), 60자 안팎, 여러 질문 이어 붙이기·긴 인용 금지.
- 논문 Abstract 질문은 Abstract 전체(최대 180자)를 인용하던 것을 첫 문장 60자까지만 인용하도록 줄였습니다.
- AI가 규칙을 어길 수 있어 길이를 서버에서 강제로 자르지는 않습니다(문장이 중간에 끊기는 것을 막기 위해).

### 4단계 — 카메라 자세·시선 분석 (2026-11-24)

시작 화면에서 "카메라로 자세·시선 분석"을 켠 경우에만 동작합니다(기본 꺼짐). 카메라나 분석 기능을 못 켜도 음성 면접은 그대로 진행합니다.

- **영상은 서버로 보내지 않습니다.** 브라우저에서 MediaPipe Face Landmarker로 약 5fps 분석하고, 답변마다 숫자 요약만 답변 녹음과 함께 보냅니다 → `interview_questions.camera_metrics` (`pnpm --filter @workspace/db run push` 필요).
- MediaPipe는 번들에 넣지 않고 켰을 때만 CDN에서 고정 버전(`@mediapipe/tasks-vision@0.10.14`, 얼굴 모델 float16)을 불러옵니다 — `artifacts/job-doc-check/src/lib/face-tracker.ts`.
- 면접 중 작은 내 화면 미리보기와 "카메라 렌즈를 봐 주세요 / 얼굴이 보이지 않아요" 안내를 보여 줍니다.
- 결과 화면 "자세·시선 분석" 카드와 종합 평가 프롬프트 한 줄 요약. 말버릇 분석처럼 조회할 때마다 규칙으로 계산합니다(AI 호출 없음) — `artifacts/api-server/src/lib/camera-posture.ts`.

| 지표 | 판정 (브라우저, `camera-analysis.ts`) | 연습 포인트가 나오는 기준 (서버) |
|---|---|---|
| 얼굴이 보인 시간 | 얼굴이 정확히 하나 잡힌 프레임 | 80% 미만 |
| 카메라를 바라본 시간 | 고개 좌우·상하 15° 이내 + 눈동자가 크게 벗어나지 않음 | 70% 미만 (50% 미만은 "부족") |
| 고개를 돌린 시간 | 좌우 20° 초과 | 20% 초과 |
| 고개를 숙이거나 든 시간 | 상하 20° 초과 | 20% 초과 |
| 고개 기울임 | 기울기 12° 초과 | 30% 초과 |
