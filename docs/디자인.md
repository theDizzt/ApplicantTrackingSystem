# My ATS 디자인 현황 및 변경 가이드

이 문서는 `artifacts/job-doc-check`에 현재 구현된 디자인을 기록한 기준 문서다.
향후 화면을 다시 디자인하거나 디자인 시스템을 정리할 때, 기존 기능과 사용자 흐름을 유지하면서 안전하게 변경하기 위한 참고 자료로 사용한다.

## 1. 제품과 디자인 방향

### 제품 표기

- 제품명: **My ATS**
- 영문 설명: **Applicant Tracking System**
- 한국어 설명: **AI 서류 심사관**
- 핵심 메시지: 이력서와 지원 회사를 AI로 분석하여 합격 가능성을 높이는 채용 준비 서비스
- 로고: `artifacts/job-doc-check/public/logo.png`
- 파비콘: `artifacts/job-doc-check/public/favicon.svg`

### 시각적 방향

- 기업용 ATS가 주는 신뢰감과 AI 분석 제품의 정밀함을 함께 표현한다.
- 대표 색상은 Blue 600이며, 기본 배경과 텍스트에는 Slate 계열을 사용한다.
- 앱 내부는 밝은 배경, 흰색 카드, 얇은 테두리, 중간 정도의 라운드를 중심으로 구성한다.
- 합격, 경고, 실패, 정보는 각각 emerald/green, amber/orange, rose/red, teal/blue 계열로 구분한다.
- 랜딩 페이지는 앱 내부보다 마케팅 성격이 강하다. 네이비와 블루 그라디언트, 블루 글로우, 장식용 그리드와 물결 SVG, 큰 헤드라인을 사용한다.
- 관리자 화면은 일반 앱과 분리된 다크 Slate 스타일이다. 일반 화면의 밝은 토큰으로 일괄 변경하지 않는다.

## 2. 디자인 토큰

전역 토큰과 Tailwind 연결은 다음 파일을 기준으로 한다.

- `artifacts/job-doc-check/src/index.css`

### 기본 색상

| 용도 | 현재 값 또는 방향 |
| --- | --- |
| 배경 | Slate 50, `210 40% 98%` |
| 기본 텍스트 | Slate 900, `222 47% 11%` |
| 카드 | 흰색 계열 |
| 테두리 | Slate 200, `214 32% 91%` |
| Primary | Blue 600, `221 83% 53%` |
| Muted | 옅은 Slate 배경과 보조 텍스트 |
| Destructive | Red 500 계열 |
| Success | Green 500 계열 |
| Warning | Orange 500 계열 |

전역 CSS 변수에는 다음 의미 토큰이 있다.

- `background`, `foreground`
- `card`, `card-foreground`
- `popover`, `popover-foreground`
- `primary`, `primary-foreground`
- `secondary`, `secondary-foreground`
- `muted`, `muted-foreground`
- `accent`, `accent-foreground`
- `border`, `input`, `ring`
- `destructive`, `success`, `warning`
- chart 및 sidebar 관련 토큰

### 다크 모드

- `.dark`에서 배경과 카드가 Slate 900 계열로 변경된다.
- Primary는 다크 모드에서도 Blue 600을 유지한다.
- 전역 다크 토큰은 정의되어 있지만, 현재 사용자 화면에는 명시적인 다크 모드 전환 UI가 없다.
- 랜딩, 구독, 관리자 화면에는 직접 지정한 `white`, `slate`, `blue` 클래스가 많다.
- 다크 모드를 정식 지원하려면 토큰만 바꾸지 말고 랜딩, 구독 카드, 관리자 화면의 대비를 별도로 점검해야 한다.

### 의미 색상

- 합격 및 긍정 결과: green/emerald
- 주의 및 개선 필요: amber/orange
- 실패 및 부정 결과: red/rose
- 정보 및 분석 결과: blue/teal

색만으로 상태를 전달하지 않는다. Badge, 아이콘, 제목, 설명 문구를 함께 사용한다.

## 3. 타이포그래피

### 폰트

- 영문 우선 폰트: `Plus Jakarta Sans`
- 한국어 폴백: `Noto Sans KR`
- 외부 폰트 선언 위치: `artifacts/job-doc-check/src/index.css`
- 기본 sans: `var(--app-font-sans)`
- 숫자 및 점수: Menlo 계열 mono 폰트 사용
- serif 폴백: Georgia

### 사용 규칙

- 페이지 제목: `font-bold` 또는 `font-extrabold`, `tracking-tight`
- 카드 제목: `font-semibold`
- 본문: regular 또는 medium
- 보조 설명: `text-muted-foreground`
- 점수와 주요 수치: `font-mono`를 섞어 분석 결과의 정밀함을 강조
- 랜딩 히어로: 매우 큰 굵은 제목과 짧은 설명문

## 4. 간격, 라운드, 그림자

### 간격

- Tailwind 기본 4px 단위를 사용한다.
- 앱 셸 내부 여백: 모바일 `p-4`, 데스크톱 `md:p-8`
- 카드 내부 여백은 주로 `p-4`~`p-8`
- 요소 그룹은 `gap-2`, `gap-4`, `gap-6`, `space-y-4`를 주로 사용한다.

### 라운드

- 기본 radius: 8px
- sm: 4px
- md: 6px
- lg: 8px
- xl: 12px
- 강조 카드: `rounded-xl` 또는 `rounded-2xl`
- Badge와 pill: `rounded-full`

### 그림자와 elevation

- 일반 카드: 경계선 중심, 필요할 때 `shadow-sm`
- 강조 카드와 랜딩 CTA: `shadow-md`, `shadow-xl`, blue 계열 그림자
- 전역 상호작용 유틸:
  - `.hover-elevate`
  - `.active-elevate`
  - `.toggle-elevate`

- `md` 미만에서 상단 sticky bar로 전환

- 플랜 카드에 `bg-white dark:bg-slate-50 text-slate-900` 같은 직접 색상 지정이 있다.
- 다크 모드 재설계 시 의도적으로 밝은 카드인지 확인해야 한다.

### 7.11 관리자 화면

경로와 파일:

- `/admin/login`: `src/pages/admin/login.tsx`
- `/admin`: `src/pages/admin/index.tsx`

일반 사용자 AppShell과 분리된 다크 화면이다.

구성:

- 다크 로그인 카드

- 조직 등록 관리 테이블
- 등록/편집 Dialog
- polling 상태
- loading/error/empty 상태

관리자 화면의 `bg-slate-900`, slate border와 text는 독립된 시각 체계다. 일반 사용자 토큰으로 기계적으로 치환하지 않는다.

### 7.12 현재 없는 화면

현재 별도의 설정 또는 프로필 페이지는 없다. 사용자 정보는 AppShell 하단에만 표시한다.

- `AppShell` 메뉴

- 구독 관리 화면과의 역할 구분

을 함께 설계한다.

## 9. 반응형 기준

Tailwind 기본 breakpoint를 사용한다.

| 구간 | 기준 | 주요 변화 |
| --- | --- | --- |
| sm | 640px | 랜딩 CTA와 일부 텍스트 배치 변화 |
| md | 768px | 모바일 상단바에서 고정 사이드바로 전환, 카드 열 증가 |
| lg | 1024px | KPI 4열, 랜딩 기능 4열 등 |

### 모바일 원칙

- 가로 flex는 세로로 쌓는다.
- 버튼과 카드는 필요할 때 전체 폭을 사용한다.
- 본문 여백은 `p-4`를 기본으로 한다.
- 분석/면접 상세의 긴 정보가 화면 밖으로 나가지 않도록 한다.
- 관리자 테이블은 가로 스크롤 또는 모바일 대체 레이아웃을 확인한다.
- 전용 hook은 `src/hooks/use-mobile.tsx`에 있지만 AppShell은 CSS breakpoint를 중심으로 작동한다.

## 10. 상태와 상호작용

### 데이터 처리

- API client: `@workspace/api-client-react`
- 서버 상태: React Query
- 전역 provider: `src/App.tsx`
- 알림: Sonner toast

### 로딩

- 목록: Skeleton 카드
- 상세: Skeleton 또는 상태 설명
- mutation: 버튼 disabled와 진행 중 문구
- AI 작업: Spinner/Clock/상태 설명

### 빈 상태

- 점선 테두리 카드
- 중앙 정렬 아이콘과 설명
- 신규 등록 또는 시작 CTA

### 오류

- 폼 필드 오류
- 폼 root 오류
- toast 오류
- 실패 상태 Badge 및 설명

모든 페이지에 명시적 error boundary가 있는 것은 아니다. 재설계 과정에서 retry UI를 추가할 수 있지만 기존 query key와 mutation 흐름은 유지한다.

### 선택과 hover

- 선택: Primary border/ring/background
- hover: Primary border 또는 muted background
- 활성 내비게이션: Primary 배경
- 클릭 가능한 카드: 전체 카드가 링크

카드 링크는 키보드 Enter로도 사용할 수 있어야 하며 focus 스타일을 제거하지 않는다.

## 11. 접근성 기준

재설계 시 다음을 필수로 확인한다.

- 제목 계층 유지
- 본문과 배경 대비 4.5:1 이상
- visible focus ring
- 키보드 Tab/Enter/Escape 동작
- 활성 내비게이션에 `aria-current`
- 모바일 메뉴에 `aria-expanded`
- Dialog의 focus trap과 Escape 닫기
- Input과 Label 연결
- 오류 문구와 입력 필드 연결
- 로고 alt에 제품명 사용
- 장식 SVG는 `aria-hidden`
- Progress와 차트에 텍스트 대체 정보 제공
- 상태는 색상뿐 아니라 Badge, 아이콘, 텍스트로 함께 전달

## 12. 디자인 변경 시 보존해야 하는 기능

디자인만 변경할 때 다음 요소는 제거하거나 임의로 변경하지 않는다.

- toast 성공/실패 피드백
- 이력서 editor DOM과 저장 흐름
- 인쇄/PDF DOM과 CSS
- 면접의 회사/이력서 선택 정보
- 심사 상태와 결과 의미색
- Dialog 및 AlertDialog 동작
- `data-*` 상태 속성

## 13. 권장 디자인 변경 순서

1. 변경 목적과 대상 화면을 정한다.
2. `src/index.css`의 semantic token을 먼저 조정한다.
3. Button, Card, Badge, Input 등 공통 UI primitive를 수정한다.
4. AppShell과 전역 레이아웃을 수정한다.
5. 반복 패턴을 공통 컴포넌트로 정리한다.
6. 랜딩, 심사 상세, 관리자처럼 하드코딩 색상이 많은 화면을 별도로 수정한다.
7. 모든 상태를 확인한다.
8. 모바일과 데스크톱을 함께 검증한다.

새 토큰을 추가할 때 권장하는 의미:

- brand
- info
- success
- warning
- danger
- surface
- surface-elevated

페이지별 `bg-slate-*`, `text-blue-*`를 한 번에 제거하지 말고 의미 토큰으로 점진적으로 교체한다.

## 16. 문서 유지 규칙

- 디자인을 변경하면 이 문서도 함께 갱신한다.
- 실제 코드와 문서가 다르면 코드를 현재 기준으로 보고 문서를 수정한다.
- 새 페이지를 추가하면 페이지 구조, 주요 상태, 반응형 동작을 기록한다.
- 새로운 공통 컴포넌트나 토큰을 추가하면 파일 위치와 사용 원칙을 기록한다.
- 기능 변경 내역이 아니라, 다음 디자인 작업자가 알아야 할 현재 시각 구조와 보존 조건을 기록한다.
