# 개발 로드맵

핵심 컨셉은 **"왜 떨어졌는가"** 와 **"면접 대비"** 두 가지입니다. 모든 기능은 "내가 이 회사에 얼마나 적합한가"를 보여주고 강점을 어필하도록 돕는 방향으로 만듭니다.

## 우선순위

| 순서 | 작업 | 내용 | 상태 |
|---|---|---|---|
| 1 | 심사 결과 구조화 + 근거 시각화 | AI 응답을 "항목별 점수 · 근거 문장 · 부족한 요건" 구조로 바꾸고 심사 결과 화면에 표시 | 구현 완료 (실환경 확인 전) |
| 2 | 불합격 예상 원인 리포트 | 1의 부족한 요건을 모아 "떨어질 수 있는 이유 Top 3"와 "이렇게 어필하세요"로 정리 | 구현 완료 (실환경 확인 전) |
| 3 | 꼬리 질문 면접 | 1·2에서 찾은 약점으로 면접 질문을 만들고, 답변에 따라 꼬리 질문을 이어감. 음성 답변은 기존 녹음·STT 재사용 | 약점 질문·꼬리 질문 구현 완료 (실환경 확인 전), 음성 답변 예정 |
| 4 | 모델 역할 분리 | 심사 / 근거 추출 / 면접 / STT / 경량 작업에 모델 5개 정도를 나눠 토큰 비용 절감 | 구현 완료 (실환경 확인 전) — 심사(기본)·면접·경량·이미지 인식 역할별 모델 + STT·임베딩. 관리자 페이지 › AI 설정 › 역할별 모델 |
| 5 | 편의 기능 | 캘린더·발표일 알림, 자격증·프로젝트·공모전 항목, 이력서 항목 통합 관리, 영어 판독, 모바일 지원, 실시간 모의 면접 | 일부 구현 (실환경 확인 전) — 지원 일정 캘린더·알림, 이력 항목 관리·이력서에 넣기. 영어 판독·실시간 모의 면접 예정 |

## 1번을 먼저 하는 이유

- 서류 심사 결과는 이미 DB(`lib/db/src/schema/analyses.ts`)에 저장되고 있지만, 점수마다 피드백이 문장 하나뿐이라 "왜 이 점수인지"를 보여줄 수 없습니다.
- 근거를 구조화해 두면 점수 시각화, 불합격 원인 리포트, 약점 기반 면접 질문(2·3번)에 그대로 다시 쓸 수 있습니다.
- 새 기능을 처음부터 만드는 대신 기존 심사 기능을 확장하는 작업이라 위험이 작습니다.

## 참고 사항

- 회사 입장에서 보는 심사 기준도 반영합니다: 논문 등급과 저자 순서, AI 작성 문장 탐지, 장기 근속 가능성 판단.
- 단순히 스펙을 높이라고 하기보다, 지원자의 강점을 회사에 맞춰 어필하는 방향으로 피드백합니다.
- 클라우드 환경에 배포해 바로 테스트할 수 있게 할 예정입니다. 코드는 자유롭게 수정하고, 기능이 겹쳐도 괜찮습니다.

## 4번 모델 역할 분리 — 구성 (2026-11-10)

같은 API 키·주소를 쓰고 역할마다 모델만 바꿉니다. 비워 둔 역할은 기본 모델을 씁니다 (`lib/openai.ts`의 `getAI(role)`).

| 역할 | 쓰는 곳 | 설정 키 | 현재 값 (HASA) |
|---|---|---|---|
| 기본(심사) | 서류 심사 3종, 불합격 원인 리포트, 모델별 의견, 커리어 분석, 자기소개서 작성 | `ai_model` | `hyperclovax-seed-32b` |
| 면접 | 면접 질문 생성, 답변 평가, 꼬리 질문 | `ai_model_interview` | `exaone-4.0-32b` |
| 경량 | 맞춤법, 이력서 파일 구조화, 기업 추천·매칭, 녹음용 질문 | `ai_model_light` | `gemma-4-31b` |
| 이미지 인식 | 스캔 PDF·이미지 공고 OCR | `ai_model_vision` | `qwen3-vl-32b` |
| STT | 음성 자기소개서 | `ai_stt_model` | `whisper-large-v3-turbo` |
| 임베딩 | 직무 문장 유사도 | `ai_embedding_model` | 미설정 (비활성) |
| 보조 심사 2·3 | 서류 심사 모델별 의견 | `ai2_*`, `ai3_*` | `exaone-4.0-32b`, `solar-open-100b` |

- 임베딩은 `bge-m3`가 동작하지만, 유사도 기준(60점)이 OpenAI 임베딩에 맞춰져 있어 그대로 켜면 거의 모든 심사에 "유사도 낮음"이 붙습니다 (테스트: 관련 문장 54점, 무관 문장 43점). 켜려면 기준값 보정이 먼저 필요합니다.
- HASA 무료 키의 하루 한도(500회)는 키 단위라, 역할을 나눠도 호출 수는 줄지 않습니다. 비용·속도·품질을 역할에 맞추는 효과만 있습니다.

## 5번 편의 기능 — 1차 구현 (2026-11-11)

| 기능 | 화면 | 내용 |
|---|---|---|
| 지원 일정 | 메뉴 › 지원 일정 (`/schedule`) | 회사별 서류 마감일·결과 발표일·면접일과 지원 상태(관심~최종 합격·불합격)를 월 달력과 "다가오는 일정"으로 표시. 날짜는 지원 회사 수정 화면의 "지원 일정"에서 입력 |
| 일정 알림 | 메뉴 배지·대시보드 배너·브라우저 알림 | 오늘~3일 뒤 일정 수를 메뉴에 배지로, 대시보드에 배너로 표시. "브라우저 알림 켜기"를 누르면 앱을 열어 둔 동안 일정마다 하루 한 번 브라우저 알림. 최종 합격·불합격 회사의 마감·면접은 제외 |
| 이력 항목 | 메뉴 › 이력 항목 (`/profile`) | 자격증·어학·프로젝트·수상/공모전·대외활동·경력·교육을 한 곳에 등록·수정·삭제 (`profile_items` 테이블, `/api/profile-items`) |
| 이력서에 넣기 | 이력서 편집 › "이력 항목 넣기" | 고른 항목을 종류별 소제목·목록으로 이력서 내용 끝에 붙임. 저장해야 반영 |

- DB: `companies`에 `application_status`, `deadline_date`, `announcement_date`, `interview_date` 열, 새 테이블 `profile_items` (`pnpm --filter @workspace/db run push`로 적용).
- 알림은 서버 푸시가 아니라 브라우저가 앱을 열어 둔 동안만 동작합니다. 이메일·휴대폰 알림은 아직 없습니다.
- 모바일: 새 화면은 좁은 화면에서 달력 칸을 점으로 줄이고, 메뉴 버튼에 일정 표시 점을 띄웁니다. 기존 화면 전체의 모바일 점검은 따로 해야 합니다.
